# Plinth POC — Implementation Plan

> **Scope:** Data platform and ingestion pipeline (breadth-first). Report generation is a subsequent phase.
> **Environment:** Single dev machine, Docker Compose, local network only. No cloud. No prod separation during POC.
> **Geographic start:** Northeastern Oklahoma. Expand regionally/nationally in later phases.
> **Stack:** Python (uv) · FastAPI · PostgreSQL 15 + PostGIS · MinIO · Prefect · Mapbox

---

## Hardware Recommendation

The full national dataset for Phase 1 is 500 GB–2 TB of raw data (DEMs, FEMA NFHL, SSURGO, NLCD, NHDPlus HR). Plan for it even though POC starts regionally.

| | Minimum (POC only) | Recommended (grows to national) |
|---|---|---|
| **CPU** | 8-core | 12–16 core |
| **RAM** | 32 GB | 64 GB |
| **SSD (OS + Postgres + Docker)** | 512 GB NVMe | 1 TB NVMe |
| **HDD (MinIO raster tiles)** | 2 TB | 4–8 TB |
| **Approx. cost (used server)** | ~$400–500 | ~$600–900 |

**Best value: used Dell PowerEdge R730 or HPE DL380 Gen9** on eBay — enterprise DDR4, dual-socket Xeon, hot-swap bays, easily upgradeable. Expect $500–800 for a 64 GB / 12-core / 4 TB config.

> PostgreSQL + PostGIS needs 8–16 GB RAM headroom for spatial index builds. GDAL/rasterio workers use 4–8 GB per concurrent process. Prefect, MinIO, and app containers add ~4 GB. 32 GB is workable for regional; 64 GB is comfortable for national parallel ingestion.

## Phase 1 — Foundation Database Schema

Before any data is loaded, the schema scaffolding must exist.

### 1.1 Core Registry & Infrastructure Tables

```sql
-- Every data source. Populated by ingestor code on first run.
CREATE TABLE data_source_registry (
    source_name          TEXT PRIMARY KEY,
    dataset_version      TEXT,
    last_downloaded      TIMESTAMPTZ,
    update_frequency     TEXT,          -- 'monthly', 'annual', 'decadal', etc.
    next_review_date     DATE,
    coverage_region      TEXT,          -- 'ne-oklahoma', 'oklahoma', 'national'
    notes                TEXT
);

-- Spatial index of raster tiles stored in MinIO.
-- One row per COG tile file.
CREATE TABLE raster_tiles (
    id              SERIAL PRIMARY KEY,
    dataset         TEXT NOT NULL,      -- 'usgs-3dep', 'nlcd', 'usgs-seismic', etc.
    s3_key          TEXT NOT NULL UNIQUE,
    bounds          GEOMETRY(Polygon, 4326) NOT NULL,
    resolution_m    NUMERIC,
    tile_id         TEXT,               -- source tile identifier
    dataset_version TEXT,
    created_at      TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX raster_tiles_bounds_idx ON raster_tiles USING GIST (bounds);
CREATE INDEX raster_tiles_dataset_idx ON raster_tiles (dataset);

-- Cache for expensive spatial queries (demographics, flood zone, etc.)
-- Keys are dataset-specific, NOT flat proximity hashes.
CREATE TABLE query_cache (
    cache_key        TEXT PRIMARY KEY,  -- compound: dataset:version:entity_id
    dataset          TEXT NOT NULL,
    input_lat        NUMERIC,
    input_lon        NUMERIC,
    result_json      JSONB,
    cached_at        TIMESTAMPTZ DEFAULT now(),
    expires_at       TIMESTAMPTZ         -- NULL = no expiry (use for stable data)
);
CREATE INDEX query_cache_expires_idx ON query_cache (expires_at)
    WHERE expires_at IS NOT NULL;

-- Archived reports (required per §11.8)
CREATE TABLE report_archive (
    report_id            TEXT PRIMARY KEY,
    generated_at         TIMESTAMPTZ DEFAULT now(),
    input_address        TEXT,
    lat                  NUMERIC,
    lon                  NUMERIC,
    source_versions_json JSONB,         -- snapshot of data_source_registry
    pdf_storage_key      TEXT            -- MinIO key
);
```

## Phase 2 — Vector Data Ingestion (Regional)

Each ingestor follows the `BaseIngestor` contract:
1. **Download** — idempotent fetch to local staging dir
2. **Validate** — check file integrity, record count sanity
3. **Load** — upsert into PostGIS (never truncate/reload blindly)
4. **Register** — upsert row in `data_source_registry`

Start with northeastern Oklahoma bounding box. Each ingestor accepts a `--region` flag or reads `REGION_BBOX_*` from env. Expanding to state or national is a config change, not a code change.

### 2.1 Census TIGER — Block Groups

| | |
|---|---|
| **Source** | Census TIGER/Line block groups |
| **Access** | Download state shapefile |
| **PostGIS table** | `census_block_groups` — geometry + GEOIDs + state/county FIPS |
| **Index** | GIST on geometry |
| **Refresh** | Annual (on ACS release) |
| **Regional clip** | Filter by state FIPS (Oklahoma = 40) initially |

> ACS demographic values (income, age, population, etc.) are fetched via Census API at query time and cached — they are not bulk-loaded. The TIGER geometries are what we store.

### 2.2 FEMA NFHL — Flood Zones

| | |
|---|---|
| **Source** | FEMA National Flood Hazard Layer (~3,200 county GDBs) |
| **Access** | Download county GDB for each target county |
| **PostGIS tables** | `fema_flood_zones` (FLD_HAZ_AR layer) · `fema_unmapped_areas` (derived — areas with no FEMA coverage) |
| **Key fields** | `fld_zone`, `zone_subty`, `sfha_tf`, `bfe_revert`, `static_bfe`, snapshot date |
| **Critical requirement** | Build `fema_unmapped_areas` layer from county boundary minus `fld_zone` polygons. A site with no FEMA data must **never** silently appear as Zone X. |
| **Index** | GIST on geometry |
| **Refresh** | Monthly — compare FEMA NFHL last-modified header against local snapshot |

> County GDB schema varies across releases. Document the field mapping in `data_source_registry.notes`.

Note: bdc.fcc.gov forces HTTP/2 (ALPN h2) and the Python HTTP/2 client (httpx + h2) triggers a server-side stream reset; the ingestor uses `subprocess` + `curl` for all FCC HTTP calls as a reliable workaround.

## Phase 3 — Raster Data Ingestion

Rasters are stored as Cloud-Optimized GeoTIFFs (COGs) in MinIO. PostGIS holds only the tile index (`raster_tiles`). Queries clip the bounding box from the COG at query time using GDAL/rasterio.

**COG pipeline per dataset:**
1. Download source raster (national or regional)
2. Reproject to EPSG:4326 if needed
3. Convert to COG (`gdal_translate` with tiling + overviews)
4. Upload to MinIO with structured key: `{dataset}/{version}/{tile_id}.tif`
5. Insert row into `raster_tiles`

### 3.1 USGS 3DEP — Digital Elevation Model (~25m effective)

| | |
|---|---|
| **Source** | USGS 3DEP ArcGIS ImageServer — `exportImage` endpoint |
| **Access** | `https://elevation.nationalmap.gov/arcgis/rest/services/3DEPElevation/ImageServer` |
| **Strategy** | Export full region bbox at max 8,000×8,000 px → single clipped GeoTIFF |
| **Effective resolution** | ~25 m over NE Oklahoma bbox |
| **Storage** | ~205 MB COG; single tile per region |
| **MinIO key pattern** | `usgs-3dep/{year}/{region}.tif` |
| **Derived products** | Slope raster — computed at query time via `gdal.DEMProcessing` with edge buffering |
| **Refresh** | Annual check |

> **Slope computation note:** Clip DEM with at least 1 grid cell (~25m) buffer beyond the AOI *before* computing slope. Clipping exactly to AOI produces incorrect edge values.

### 3.2 NLCD — National Land Cover Database

| | |
|---|---|
| **Source** | MRLC NLCD 2021 via GeoServer WCS (`subsettingCrs=EPSG:4326`) |
| **Access** | `https://www.mrlc.gov/geoserver/mrlc_display/NLCD_2021_Land_Cover_L48/wcs` |
| **Strategy** | WCS GetCoverage clipped to region bbox; output already in EPSG:4326 |
| **Effective resolution** | ~27 m |
| **Storage** | ~12 MB COG; single tile per region |
| **MinIO key pattern** | `nlcd/{year}/{region}.tif` |
| **Key fields (categorical)** | NLCD class code → class name lookup table in Postgres |
| **Refresh** | Annual check |

> Note: WCS `subset` using EPSG:3857 coordinates is rejected by the MRLC GeoServer ("Unable to map projection Popular Visualisation Pseudo Mercator"). Must use `subsettingCrs=http://www.opengis.net/def/crs/EPSG/0/4326` with `Long()`/`Lat()` axis labels.

## Phase 5 — Prefect Flows (Scheduled Refresh)

### 5.1 Flow Design

| Flow | Schedule | Trigger |
|---|---|---|
| `ingest-all-regional` | On-demand | Initial setup and teardown/rebuild |
| `refresh-fema-nfhl` | Monthly | Compare FEMA last-modified header vs. local snapshot |
| `refresh-annual` | Annual (Jan 1) | Census ACS, SSURGO, NLCD, 3DEP, USDA WHP (API cache clear), NOAA Normals |
| `check-staleness` | Weekly | Alerts if any source exceeds `next_review_date` in registry |
| `cache-expire` | Daily | Purges expired rows from `query_cache` |

### 5.2 FEMA Refresh Logic

```
1. HEAD request to FEMA NFHL endpoint
2. Compare Last-Modified against data_source_registry.last_downloaded
3. If delta detected:
   a. Download updated county GDB(s)
   b. Validate schema
   c. Upsert into fema_flood_zones (replace by county)
   d. Rebuild fema_unmapped_areas for affected counties
   e. Clear query_cache rows where dataset = 'fema-nfhl'
   f. Update data_source_registry
4. Emit structured log with outcome
```

### 5.3 Idempotency & Repeatability

Every flow must be safe to re-run:
- Downloads use content-hash or ETag checks — don't re-download unchanged files
- DB loads use `INSERT ... ON CONFLICT DO UPDATE` (upsert), never `TRUNCATE + INSERT`
- MinIO uploads use `--if-not-exists` semantics (check before upload)
- `bootstrap.sh` + `plinth-cli ingest all` = full rebuild from scratch in one command

## Phase 6 — Query Layer (Spatial Lookups)

Before report generation, validate that point-in-polygon and nearest-feature queries work correctly.

### 6.1 Core Query Functions

Implement and test each as a standalone Python function with input `(lat, lon)`:

| Function | Description |
|---|---|
| `query_flood_zone(lat, lon)` | Point-in-polygon against `fema_flood_zones`. Returns zone, subtype, BFE, snapshot date. Falls back to `fema_unmapped_areas` check. |
| `query_fema_nri(lat, lon)` | Find Census tract containing point → join to `fema_nri` |
| `query_iecc_zone(lat, lon)` | Point-in-polygon → climate zone label + description |
| `query_census_block_groups(lat, lon, radii_mi)` | Area-weighted intersection for 1/5/10-mi buffers. Uses PostGIS `geography` type. |
| `query_elevation(lat, lon)` | Find tile in `raster_tiles` → clip COG from MinIO → extract value |
| `query_slope(lat, lon, radius_m)` | Clip buffered DEM → run `DEMProcessing` → extract mean/max |
| `query_land_cover(lat, lon, radius_m)` | Clip NLCD → mode classification + impervious % |
| `query_soil(lat, lon)` | Point-in-polygon `ssurgo_mapunits` → join to `muaggatt` + `component` |
| `query_hydro(lat, lon, radius_mi)` | Nearest named waterbody/flowline from NHD tables |
| `query_seismic_pga(lat, lon)` | USGS Design Maps API → PGA value (cached) |

| `query_noaa_normals(lat, lon)` | Nearest station within 50 mi — flag if >15 mi |
| `query_nasa_power(lat, lon)` | Cache check → API call → cache store |
| `query_epa_aqs(lat, lon)` | Nearest monitor within 50 mi → PM2.5 + ozone |
| `query_earthquakes(lat, lon)` | M3+, 50 mi, 50 yr → count + max magnitude |

## Phase 7 — Report Generation (Incremental)

Report generation is intentionally staged. Build and validate each section before adding the next. Each step produces a renderable PDF.

**PDF stack:** WeasyPrint + Jinja2. Maps rendered as PNGs via Mapbox Static Images API. Charts via matplotlib (saved as PNG). All embedded in HTML template → PDF.

> **Per requirements §5.2:** Prototype the full PDF layout (all 8 sections, realistic data) before wiring live data to each section. WeasyPrint layout issues compound in long documents.

### Step 7.1 — PDF Skeleton (All Sections, Mocked Data)

Build the full 8-section HTML/CSS template with hardcoded placeholder data. Validate layout, typography, page breaks, map placeholders, and disclaimer placement.

Checklist:
- [ ] Cover page: address, coordinates, report date, report ID, "Prepared for", prominent disclaimer block, QR code placeholder
- [ ] Section 1: Executive Summary + Risk Summary Table (tabular, no color coding)
- [ ] Sections 2–7: All section headers, table layouts, map image placeholders
- [ ] Section 8: Methodology / Sources table
- [ ] Footer: subtle persistent `Plinth · site-intelligence.com · Report ID: [XXXXX]`
- [ ] Appendix page: "About this report" + soft CTA
- [ ] Map attribution: "© Mapbox © OpenStreetMap contributors" on every map

### Step 7.2 — Wire Flood Risk (Section 2 partial)

Connect `query_flood_zone()` to the template. Validate:
- Zone X (mapped low risk) vs. Zone AE (high risk) vs. unmapped display correctly
- NFHL snapshot date appears
- Inline disclaimer adjacent to flood zone field
- Flag language per requirements (data + direction, no insurance conclusions)

### Step 7.3 — Wire Demographics (Section 6)

Connect `query_census_block_groups()` + Census ACS API. Validate:
- Three radius buffers labeled "straight-line radius"
- ACS vintage year displayed
- Area-weighted intersection math checked against manual calc

### Step 7.4 — Wire Physical Context (Section 3)

Connect elevation, slope, land cover, hydrography queries. Validate slope disclaimer at >15%.

### Step 7.5 — Wire Climate & Solar (Section 4 + 5)

### Step 7.6 — Wire Environmental Risk: Soil, Seismic, Wildfire, Air Quality (Section 2 remainder)

### Step 7.7 — Wire FEMA NRI + Infrastructure (Section 2 + 7)

### Step 7.8 — Wire Mapbox Static Maps

### Step 7.9 — Executive Summary (Section 1)

### Step 7.10 — Methodology Section (Section 8)
